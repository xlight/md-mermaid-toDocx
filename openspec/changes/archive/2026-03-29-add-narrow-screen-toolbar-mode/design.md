## Context

当前响应式设计使用 `@media (min-width: 1024px)` 区分桌面端和移动端：
- 桌面端（≥1024px）：左右分栏 + 单层工具栏
- 窄屏端（<1024px）：上下布局 + 工具栏换行

问题：
1. 工具栏在窄屏下没有专门设计，换行后控件堆叠混乱
2. 次要控件（GitHub、Star、语言）与主控件混杂，不便于操作
3. 垂直空间被工具栏过度占用，编辑/预览区域可用空间减少

用户期望：在窄屏下仍能方便地进行核心操作（编辑、切换视图、导出文档）。

## Goals / Non-Goals

**Goals:**
- 在窄屏（<1024px）下提供清晰、紧凑的工具栏布局
- 优先保证核心操作（字体、视图模式、生成DOCX）的可访问性
- 次要控件（GitHub、Star、语言）收纳到折叠菜单
- 减少工具栏占用的垂直空间

**Non-Goals:**
- 不改变桌面端的现有布局（保持单层工具栏）
- 不引入新的构建依赖
- 极窄屏（<480px）的底部固定栏作为可选优化，MVP 阶段暂不实现

## Decisions

### 1) 采用渐进式折叠策略

工具栏控件按优先级分三层：
- **核心层**：始终可见 —— 字体选择器、视图模式按钮、生成DOCX按钮
- **扩展层**：空间允许时显示 —— 主题配置、输出模式
- **收纳层**：默认折叠 —— GitHub、Star、语言切换

**Rationale:** 核心操作必须随时可见，收纳层使用频率低，折叠后不影响主流程。

### 2) 使用 CSS Grid/Flexbox 实现紧凑布局

在窄屏媒体查询中使用更紧凑的 flex 排列：
- 控件间距从 6-8px 缩减到 4px
- 使用图标替代部分文字标签
- 字体选择器在窄屏下使用更窄的最小宽度

**Rationale:** CSS 实现简单，不需要修改 HTML 结构。

### 3) 折叠菜单使用原生 HTML `<details>`/`<summary>`

不引入第三方dropdown库，使用 HTML 原生折叠元素：
```html
<details class="toolbar-more-menu">
  <summary>更多</summary>
  <div class="menu-content">
    <!-- 收纳的控件 -->
  </div>
</details>
```

**Rationale:** 无需 JS 交互，原生支持键盘无障碍，样式可自定义。

### 4) 极窄屏（< 480px）保持进一步简化

当屏幕 < 480px 时：
- 字体选择器改为图标按钮（点击弹出选择）
- 视图模式仅保留核心切换

**Rationale:** 极窄屏空间极度有限，需要更激进的简化。

## Risks / Trade-offs

- **折叠菜单可触性**：在触摸屏上 `<details>` 行为需测试
- **i18n 文本长度**：中文"更多"比英文"More"更长，可能影响紧凑布局
- **现有布局兼容性**：窄屏修改不应影响桌面端布局

## Implementation Approach

### Phase 1: CSS 紧凑布局（不新增 HTML）
1. 在 `styles.css` 添加 `@media (max-width: 1023px)` 规则
2. 缩小控件间距、减少 padding、使用紧凑字体大小
3. 调整视图模式按钮组为更窄的显示

### Phase 2: 折叠菜单（新增 HTML + CSS）
1. 在 `index.html` 添加 `<details>` 包裹收纳控件
2. 样式化折叠菜单为下拉/弹出形式
3. 确保触摸友好

### Phase 3: 极窄屏优化（可选）
1. 添加 `@media (max-width: 480px)` 规则
2. 进一步简化控件显示
