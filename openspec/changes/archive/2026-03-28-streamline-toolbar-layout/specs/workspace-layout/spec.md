## ADDED Requirements

### Requirement: 单层工具栏 SHALL 表达清晰的工作流层级

系统 SHALL 在单层顶部工具栏中明确区分身份信息、工作区控制和输出动作，使用户能够快速识别主工作流而不增加额外工具栏行。

#### Scenario: 主工作流优先级清晰
- **WHEN** 用户打开页面
- **THEN** 工具栏中的编辑配置、视图模式入口和导出动作具有清晰的先后层级

#### Scenario: 保持单层布局
- **WHEN** 用户在桌面端查看页面
- **THEN** 工具栏保持单层呈现而不是增加第二行控制栏

### Requirement: 低频全局入口 SHALL 被弱化但保留

系统 SHALL 保留 GitHub / Star / 语言切换等低频入口，但它们 MUST 不与主按钮拥有相同视觉优先级。

#### Scenario: 外链入口弱化
- **WHEN** 用户查看工具栏
- **THEN** GitHub 与 Star 入口以轻量形式呈现，不压过编辑与导出控件

#### Scenario: 语言切换不打断主流程
- **WHEN** 用户准备编辑或导出文档
- **THEN** 语言切换入口存在但不会占据与主操作相同的视觉权重

### Requirement: 状态反馈 SHALL 脱离主控制流

系统 SHALL 将状态反馈从主工具栏控件流中分离，避免状态文本与按钮、选择器并排争抢注意力。

#### Scenario: 生成状态反馈
- **WHEN** 用户触发 DOCX 导出或其他耗时操作
- **THEN** 状态信息显示在独立反馈区域，而不是挤占主工具栏控制位

#### Scenario: 错误状态反馈
- **WHEN** 系统出现渲染或导出错误
- **THEN** 错误提示保持可见且不破坏工具栏控件的布局稳定性

### Requirement: 工具栏 SHALL 为视图模式预留稳定入口

系统 SHALL 在单层工具栏中为后续 split / preview 等视图模式保留稳定位置，避免未来新增入口时再次重排整个工具栏。

#### Scenario: 视图模式入口位置稳定
- **WHEN** 用户查看工具栏中的工作区控制区域
- **THEN** 视图模式入口位于与字体、图表配置相邻的工作区控制区域中

#### Scenario: 后续扩展不破坏主布局
- **WHEN** 系统后续加入 split / preview 视图切换
- **THEN** 无需重新定义工具栏整体信息架构即可接入该入口

### Requirement: 单层工具栏 SHALL 尽量减少换行导致的高度损失

系统 SHALL 优化单层工具栏的横向空间分配，减少桌面常见宽度下因换行造成的内容区高度压缩。

#### Scenario: 中等桌面宽度下稳定显示
- **WHEN** 用户在常见桌面宽度下打开页面
- **THEN** 工具栏优先保持单行稳定显示，避免因控件拥挤频繁换行

#### Scenario: 窄宽度下优先保留主操作
- **WHEN** 可用横向空间不足
- **THEN** 系统优先保证主工作流控件和导出按钮的可见性
