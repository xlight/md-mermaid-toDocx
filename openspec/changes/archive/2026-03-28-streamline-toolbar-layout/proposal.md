## Why

当前顶部工具栏将品牌信息、外链、编辑配置、导出操作、语言切换和状态反馈平铺在同一层级，造成视觉噪音和操作优先级不清。随着后续计划加入 split / preview 视图模式，若不先整理工具栏结构，顶部区域会继续膨胀并挤占编辑与预览区域的有效空间。

## What Changes

- 重新组织单层工具栏的信息层级，突出主工作流：编辑配置 -> 视图模式 -> 导出操作
- 弱化 GitHub / Star 等外链入口，减少其在主操作流中的视觉权重
- 压缩语言切换与标题区占用，降低单层工具栏的拥挤感
- 将状态反馈从主控制流中移出，避免与按钮和选择器竞争注意力
- 为未来的 Split / Preview 视图模式预留稳定、明确的入口位置
- 优化单层工具栏在不同桌面宽度下的布局稳定性，尽量避免换行导致内容区高度损失

## Capabilities

### New Capabilities
- `workspace-layout`: 定义编辑器/预览工作区的视图模式入口与单层工具栏中的布局控制规则

### Modified Capabilities
- `docx-export`: 调整工具栏中的导出操作层级与可见性，使导出主按钮在单层布局中保持清晰优先级

## Impact

- `index.html`: 调整工具栏 DOM 结构、控件顺序与未来视图模式入口位置
- `styles.css`: 重构单层工具栏的布局、间距、控件权重与响应式规则
- `app.js`: 调整 i18n 文案、状态反馈呈现位置，预留或接入视图模式控制状态
- 工具栏交互模型：重新定义哪些控件常驻、哪些弱化、哪些移出主控制流
