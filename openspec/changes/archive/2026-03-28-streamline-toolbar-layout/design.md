## Context

当前项目采用单层顶部工具栏承载几乎全部入口：标题、GitHub/Star 外链、字体选择、图表配置、导出、打印、语言切换以及状态文本。现有结构虽然直接，但随着功能增长已经出现三个问题：

1. 信息层级不清，品牌外链与主操作具有相近的视觉重量。
2. 单层工具栏过于拥挤，容易在桌面较窄宽度下换行，从而压缩下方编辑/预览区域高度。
3. 后续计划加入 split / preview 视图模式时，缺少自然的入口位置，继续平铺会进一步放大混乱。

项目约束明确：
- 保持单层工具栏，不增加新的横向控制行。
- 尽量保留现有静态 HTML + CSS + JS 架构，不引入复杂依赖。
- 需要兼容现有中英文 i18n、按钮行为和桌面/移动布局。

## Goals / Non-Goals

**Goals:**
- 在不增加垂直高度的前提下，重建单层工具栏的主次关系。
- 突出主工作流：编辑配置 -> 视图模式 -> 导出动作。
- 为未来 split / preview 视图模式预留稳定位置与状态表达。
- 减少低频入口（GitHub/Star、语言、状态）对主控制流的打扰。
- 改善桌面宽度变化时的工具栏稳定性，降低换行概率。

**Non-Goals:**
- 不在本次设计中引入双层 toolbar。
- 不在本次设计中实现完整 settings 菜单系统。
- 不改变文档编辑/预览主体结构本身（例如分栏拖拽逻辑属于后续 change）。
- 不重做整体视觉品牌，仅整理信息架构与控件权重。

## Decisions

### 1. 工具栏按单行三段逻辑组织，而不是继续平铺

采用单行中的隐式三段结构：
- 左侧：身份与轻量外链
- 中部：工作区控制（字体、图表配置、未来视图模式）
- 右侧：输出动作与全局轻设置

这样可以保持单层，同时在语义上形成主流程，而不需要额外增加第二行。

**为什么不继续平铺：** 继续平铺会让未来新增 View Mode 时进一步稀释主按钮权重。

### 2. 将导出按钮定义为唯一主按钮

`Generate DOCX` 在当前产品中是最核心的结果导向操作，应成为工具栏中唯一最高视觉等级按钮。`Print Preview` 保留为次级动作，避免两个高权重按钮争抢注意力。

**替代方案：** 让打印与导出保持同级。
**不选原因：** 会削弱导出主路径，不利于单层收敛。

### 3. 低频全局项弱化而不是消失

GitHub/Star 与语言切换仍保留，但需要降低视觉体积与交互权重：
- 外链更适合图标化或紧凑化
- 语言切换应使用轻量表达（如短标签或紧凑选择器）

**为什么不完全移除：** 这些入口仍然有价值，只是不应处于主工作流中心。

### 4. 状态反馈移出主控制流

状态文本不应继续与按钮、选择器并排存在。它应转为附着在工具栏下缘、内容区顶部或轻量 toast 的反馈层。

**原因：** 状态是反馈，不是控制；保留在主栏会持续制造“工具栏像控制台”的拥挤感。

### 5. 为未来视图模式预留明确入口

虽然本 change 不实现完整 split / preview 布局能力，但工具栏结构要预留稳定位置，使后续可自然加入 `Split | Preview` 或同等语义控件，而无需再次大范围重排。

**原因：** 这次整理如果不为未来模式切换留位，很快又会重新变乱。

## Risks / Trade-offs

- **桌面空间仍可能不足** -> 需要提前定义哪些控件在窄宽度下可缩写、图标化或降低优先级。
- **弱化 GitHub/Star 可能影响可见性** -> 保留入口但减少按钮化表达，兼顾项目传播与工作效率。
- **状态移位可能降低可发现性** -> 通过固定反馈区域或 toast 保持可见，不与控制项混排。
- **为未来视图模式预留位置但暂不实现** -> 需要在设计中明确这是“预留位”，避免用户误以为功能已完整上线。
