## Context

当前页面已经具备编辑区与预览区的双栏基础结构，但宽度是固定比例，且仅有“视图模式占位入口”，尚未形成真正可操作的工作区系统。用户提出了明确的交互约束：

- 需要鼠标拖拽中间分割线自由调节宽度
- 需要可快速切换 `editor-only` / `preview-only`
- 拖拽中不做实时重渲染，避免性能抖动
- 松手后一次性确认并触发渲染
- 不做 localStorage 持久化，仅会话内保留最近有效比例
- 当某侧宽度低于最小值时自动切换到对应单栏模式

该变更会影响布局、交互状态管理和预览刷新触发时机，但不涉及后端或依赖变更。

## Goals / Non-Goals

**Goals:**
- 提供可操作的工作区模式：`split` / `editor-only` / `preview-only`
- 在桌面端支持分割线拖拽调宽
- 拖拽松手后再渲染，保证交互流畅与行为可预测
- 通过最小宽度阈值自动进入单栏模式
- 切回 `split` 时恢复本次会话内最近有效比例

**Non-Goals:**
- 不实现比例跨刷新持久化（不写入 localStorage）
- 不实现移动端手势拖拽
- 不在本变更中引入复杂动画系统或键盘无障碍拖拽

## Decisions

### 1) 使用显式状态机管理工作区模式

采用显式状态：`split | editor-only | preview-only`，并维护会话内 `lastSplitRatio`。

**Why:** 比“用宽度推导模式”更稳定，便于模式切换和阈值切换后的恢复。

### 2) 拖拽采用“松手提交”策略

`mousedown` 进入 dragging，`mousemove` 仅更新分割线位置与临时布局，`mouseup` 才提交比例并触发一次预览更新。

**Why:** 避免 Mermaid/MathJax 在拖拽过程中高频重排，减少卡顿与视觉噪声。

### 3) 最小宽度阈值触发自动模式切换

定义 `editorMinWidth` 与 `previewMinWidth`（例如 280 / 320），当拖拽提交位置越界时自动切换至对应单栏。

**Why:** 防止出现“极窄但仍显示”的不可用布局，行为更符合用户预期。

### 4) 会话内记忆比例，不做持久化

`lastSplitRatio` 只保存在内存态。页面刷新后回到默认比例。

**Why:** 与用户明确要求一致，减少状态复杂度与持久化副作用。

### 5) 桌面启用拖拽，移动端仅保留模式切换

拖拽行为限定在桌面断点，移动端继续使用简化布局，避免触摸拖拽复杂度。

**Why:** 用最小实现覆盖主要价值场景，控制交互风险。

## Risks / Trade-offs

- **拖拽后自动切模式可能让用户意外** -> 在切换时给出轻量提示（toast）并保留快速切回入口
- **阈值设定不合理可能影响体验** -> 将阈值集中定义，便于后续调优
- **mousemove 处理不当会造成卡顿** -> 仅做轻量样式更新，不做重渲染
- **窗口外松手导致 dragging 卡死** -> 在 `window` 级监听 `mouseup` 做兜底收尾
