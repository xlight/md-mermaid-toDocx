## Context

当前布局容器使用 `100vh` 高度，工作区采用 flex 布局。在窄屏 split 模式下，编辑区和预览区为上下结构，但缺少稳定的高度分配与最小高度约束，导致预览内容增长时持续挤压编辑区可视高度。项目是纯前端无构建体系，改动应集中在 `styles.css` 和少量 `app.js` 的模式切换逻辑，不引入新依赖。

## Goals / Non-Goals

**Goals:**
- 在窄屏 split 模式下提供稳定的上下分栏体验，避免编辑区高度持续塌陷。
- 通过“弹性分配 + 最小高度”策略，让内容增长转为各自面板内部滚动。
- 保持现有 `split` / `editor-only` / `preview-only` 模式语义不变，并与桌面拖拽逻辑隔离。
- 在极短视口与移动端软键盘场景下提供可预测的兜底行为。

**Non-Goals:**
- 不引入移动端纵向拖拽分割线交互。
- 不重构滚动同步算法与锚点映射策略。
- 不修改导出、Mermaid 渲染、主题系统的行为。

## Decisions

1. 采用方案 B：窄屏 split 使用弹性高度分配并对编辑区、预览区设置最小高度。
   - Rationale: 相比 50/50 固定分配，弹性分配更适应不同设备可用高度；相比可拖拽纵向分割，复杂度与回归风险更低。
   - Alternative A (50/50 固定): 实现简单但在内容密度不均时不够灵活。
   - Alternative C (纵向拖拽): 控制力更强，但触控与可访问性复杂度高，不符合当前快速修复目标。

2. 将“高度竞争”转为“内部滚动竞争”。
   - 实现上要求编辑输入区与预览区继续保持 `overflow-y: auto`，并确保父级分栏不因内容增长突破分配高度。

3. 保持断点职责清晰：仅在 `<1024px` 的 split 布局启用该策略。
   - 桌面端（>=1024px）继续沿用现有横向分割比例与拖拽行为，避免交叉影响。

4. 增加极短视口兜底策略。
   - 当可用高度不足以同时满足两个最小高度时，允许降低到紧急最小值；若仍不足，自动切换单栏模式以保证可编辑或可预览。

## Risks / Trade-offs

- [Risk] 移动端软键盘弹出导致视口高度急剧变化，可能触发频繁重排 → Mitigation: 在 resize 处理中限制不必要的模式抖动，并优先保持当前模式稳定。
- [Risk] 最小高度阈值过大导致小屏出现双滚动体验不佳 → Mitigation: 以 320px 宽设备进行手测并校准阈值。
- [Risk] 与既有窄屏工具栏换行高度叠加，导致可用内容区过小 → Mitigation: 联合验证工具栏折叠态和 split 高度策略。
- [Trade-off] 弹性最小高度策略比固定 50/50 更复杂，但显著提升跨设备适配性。
